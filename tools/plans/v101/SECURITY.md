# v1.01 security pass — the online backend (workstream F)

Read: `server/src/index.js`, `routes.js` (every route, all blocks to v1.0), `store.js`, `jwt.js`, `harden93.js`, `server/template.yaml`
(IAM, Cognito, API Gateway throttles, the budget kill switch), and the page's online paths (`112-online` MOCK / NET, `113-onlmatch` lockstep,
`114-onlnet` sign-in, `38-matchsave` matchLoad, `309-v100replay`). The v1.0 pass (docs/backend.md "Security pass (v1.0)") is not repeated here.
Nothing secret is in this file. Nothing was deployed: the fixes ship with the next release (`bash flavius.sh release`; S4 is a template change, so
that deploy updates the stack).

## Findings

| id | severity | where | what an attacker could do | fix / status |
|---|---|---|---|---|
| S1 | **critical** | `match.open` (host's opening snapshot → every fighter, watcher, late joiner and the server replay, guests included via `#replay=`), `match.snap` (resync snapshot → the one who asked); page `matchLoad` | A snapshot is loaded with `$('#log').innerHTML = snap.log`, and its strings are drawn as HTML (`nm()` prints `u.name` and `u.color` raw into `<b style="color:…">`). A host (anyone who opens a room) or a fighter answering a resync could ship `<img src=x onerror=…>` or a colour like `red" onmouseover="…` and run script on every other screen — and on anyone opening that match's replay link. The script can read the Cognito tokens in localStorage (refresh token 30 days) → full account takeover (spend the treasury, give gear away, delete the account). | **Fixed.** Server: `C.snapBad101` refuses a snapshot carrying script-capable tags, inline handlers, script / HTML data URLs, `srcdoc` or entities inside tags (code `snap_bad`; the S JSON is parsed, so `<` escapes are seen); the opening is written **once** (a second `match.open` answers `{kept:1}` — also fixes a host who reloads overwriting the real opening). Page (`322-v101onl`): every match state it loads (online openings / resyncs through `onlmLoad`, replays, save slots) is cleaned in an inert `<template>` first (unsafe tags dropped, `on…=` / unsafe URLs / `style url()` removed, attribute break-outs lose their quotes) — this also covers openings already stored and older servers. Tests: `server/test/v101.test.js`, `tools/tests/tonl101.js` (a doctored state loads with nothing able to run; real Democritus / Familia states pass unchanged). |
| S2 | **high** | `match.input` → `onlmApply` on every other page | Lockstep inputs carry strings (`act` ids, modal values, `mode`) that the other pages hand to handlers which may print them; the server only checked size and seat. Same script-injection path as S1, one move at a time. | **Fixed.** Server refuses a move with markup before it takes a seq (`C.inBad101`, code `in_bad`); the page cleans string fields of another page's move (internal fields untouched; an honest page never sends markup). |
| S3 | **high** | `match.result` → `C.agree` → `settleMatch` | Results are by agreement of the human fighters' reports. Two accounts in one Ranked room can agree on any table (wins, CF up to 400, kills) and farm Glory, coin and rank gifts; two colluders outvote one honest player (his gladiator can be reported dead and he takes the strike); after the others abandon / are dropped, a lone report is accepted unverified and decides the dropped seats' Fate. | **Mitigated, still open.** v1.01: the table is cleaned against the room (seats 0…seats−1, one row a seat — `C.tableFix101`); every settled Ranked table with an oddity (missing human seat, several winners outside a team event, every seat won, CF ≥ 120) or accepted unverified with 2+ humans is written to `AUDIT#<match>` (GSI1 `AUDIT`, 90 days) + a `[audit101]` log line. Real fix = the server re-plays Ranked matches from its own opening + inputs (wave 2 "server Ranked check", PLAN.md); the audit items are its first evidence. S4 removes free scripted alt accounts. |
| S4 | **high** | `template.yaml` UserPool; `index.js` `$connect` | The user pool allows self sign-up (no `AllowAdminCreateUserOnly`) and the app client has the default auth flows, so Cognito's public SignUp API + the (public) client id mint unlimited native accounts that bypass Google — scripted alts for S3, guest-pass / daily-kit farming, and confirmation e-mails at the pool's cost. Their ID tokens pass `jwt.verify` (right issuer and audience). | **Fixed.** Template: `AdminCreateUserConfig: {AllowAdminCreateUserOnly: true}` (Google federation still creates its users) and Lambda env `REQUIRE_GOOGLE` (true whenever Google is configured); `$connect` then refuses an ID token without a Google identity (401). Dev stacks (`DEV_NAMES`) unchanged. Test: `v101.test.js` sign-in block. Needs the stack update at the next release. |
| S5 | low | `routes.js` `route()` | `R[t]` read inherited properties: `constructor`, `toString`, `__proto__` … reached as routes (an echo or an internal error, no damage found). | **Fixed**: own routes only (`unknown_req`); the request name in the refusal is cut to 40 characters. |
| S6 | medium | template throttles, `C.limiter93` | The general rate limit lives in each Lambda container's memory: parallel containers multiply it. The only hard cap is the stage throttle (burst 200 / 100 a second, shared by everyone) with no reserved concurrency; the budget kill switch reacts to AWS cost data that can lag by hours — a flood can cost money and lock everybody out until the 1st. | Proposal: lower the stage throttle (e.g. 100 / 50) as template parameters, reserved concurrency on the arena Lambda (the switch's "reopen" must restore it instead of deleting it; check the account's concurrency quota first), an IP-keyed in-memory limit at `$connect`, and a DynamoDB-backed bucket for the expensive routes (`hello`, `lobby.list`, `here.list`). |
| S7 | medium | `index.js` guests, `hello` / `lobby.list` for guests | A guest picks its own id: every connection can be a new guest (new `GUEST#` item, fresh 2 hours, fresh rate bucket), and guest `hello` runs `prune` (writes). | Proposal: per-IP connect quota (memory, not stored), guests' `hello` without `prune`, a cap on guest connections a minute. |
| S8 | medium | page: Cognito tokens in localStorage, no Content-Security-Policy | Any future script injection is an account takeover (S1 showed one). | Proposal: a CSP meta in `01-head` (`object-src 'none'; base-uri 'none'; connect-src` limited to the API, Cognito and the site) — `script-src` cannot be tight while the page is one inline script; refresh token 30 → 7 days. |
| S9 | medium | `114-onlnet` `$connect ?token=` | The ID token rides in the WebSocket URL; it would land in API Gateway access logs (if they are ever turned on) or a proxy's logs. | Proposal: keep access logging off (documented), or send the token in the first message after connect. |
| S10 | medium | `C.agree` lone report | (part of S3) a 2-human Ranked match where the other lanista was dropped (away 3+ min): the remaining one alone reports the dropped gladiator's Fate. Making unverified deaths not count would let a losing player pull the plug to dodge his Fate. | His call (design): proposal = an unverified lone report cannot kill the other seat when that seat's lanista was dropped, and the drop counts as a leave (`lv100`) as today. |
| S11 | low | `match.cpuheld` | Any live fighter can close a dropped seat's reclaim window at once, without the CPU turn having been reached. | Proposal: accept it only after a full rotation of turn reports (`tc100`) or from a majority. |
| S12 | low | `lobby.watch` | Anyone can bump a room's watcher counter (a versioned room write each time) — write contention on a busy room. | Proposal: count unique watchers or drop the route (match.watch already counts). |
| S13 | low | `party.join` | 5-letter party codes can be tried at the general rate; joining a stranger's party blocks its leader (`groupOf` refuses while a member is busy / houseless). | Proposal: a per-account join quota and a leader kick. |
| S14 | low | page "Online server" box (word of power) | A pasted malicious `wss://` address receives the player's ID token. | Proposal: accept only `*.execute-api.<region>.amazonaws.com` and the site's own hosts, warn otherwise. |
| S15 | low | `jwt.js` | An unknown key id never refetches the JWKS (sign-ins fail for up to an hour after a Cognito key rotation). | Proposal: refetch once on an unknown `kid` (rate-limited). |
| S16 | low | `acct.delete` | Deleting an account leaves its id on REPLAY#, LOOT#, MARKET, CHAT / FORUM lines, ADMIN log, AUDIT# (most expire by TTL). | Proposal: scrub the ids or document the retention on the privacy page. |
| S17 | info | `match.get`, seeds, Mandata, token pictures | Openings, inputs and seeds are readable by watchers (Ranked one turn behind); hidden cards reach every client; picture content is unchecked. | Known, by decision (v0.80 / v0.94 / v1.0). |
| S18 | info | IAM, secrets | Lambda role: the table + its index and ManageConnections on this API only; PITR on; logs 7 days; Google secret and TESTERS are NoEcho parameters; testers ride on the connection as a yes/no. | OK. |
