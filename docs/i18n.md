# Translations (i18n)

The game speaks English, Español, Italiano, Português (Brasil), Français, Deutsch, 日本語, 简体中文 and English (Australia).
Names and game terms (class names, ranks, Fate, Missio, Lanista, Domus, CF, AP/HP, event names …) stay English everywhere.

## How text gets translated

- Every player-facing literal goes through `_T` (00-lang): `_T('Plain text')`, `` _T`Text with ${x}` ``, or `` `<b>${_T`run`}</b>` ``
  inside HTML templates. English is the identity.
- The **key** is the English text with each `${…}` as `{0}`, `{1}` … (trimmed). A language pack `assets/lang_<l>.js`
  (`window.LANG_PACK = {l, d: {key → text}, s: [server patterns]}`) is loaded before the script, only for the picked language
  (localStorage `flavius_lang`; switching reloads). A miss shows English.
- Plurals: a translation may write `{n|one|many}` — picked by value n ('' / 1 / y / is / was / has = one).
- `TX(str)` = an exact lookup for text that never went through `_T` (01-head's static markup, server texts).
- **Server texts** (v0.93): a refusal carries `mcode` + `vals`; `SRV_TEXT93[mcode]` (src/223a, generated) gives the English
  template = the translation key, `223-v93harden` fills it in the player's language. Older servers send only English → matched by
  `TXP` (148-v86lang) against the pack's server patterns.

## Adding or changing English

1. Write the English as usual in a module (never in 111-onlcore / 14-names / 13-sim / 148 / 00c / 223a — they are skipped).
2. `node tools/i18n/wrap.js --write` (marks new literals with `_T`; `// i18n:skip` on a line stops it) and
   `node tools/i18n/frag.js --write` (short runtime words inside translated text).
3. Server texts: `node tools/i18n/srvtext93.js` (codes) + `node tools/i18n/srvkeys.js` (the list the translators see, part-25).
4. **The lead** runs `node tools/i18n/newkeys.js` (untranslated keys → the next `tools/i18n/src/part-NN.json`), translates per
   `tools/i18n/GUIDE-<l>.md` into `tools/i18n/<l>/part-NN.json`, checks with `node tools/i18n/check.js <part>`, then
   `node tools/i18n/mkdict.js` → `assets/lang_<l>.js`.

## Checks

- `node tools/i18n/check93.js` — every language: **missing** keys (used by the page, absent from the language), **unused** keys
  (kept for text nothing uses), **broken** placeholders (`{n}` differs from the key). Ceilings in the file / env
  (`I18N_MAX_MISSING`, `I18N_MAX_UNUSED`, `I18N_MAX_BROKEN`); exit 1 when over. release.sh prints it; tv93i asserts it.
- `tools/tests/tv93i.js` — **pseudolocalization**: every known key becomes `[!! Ŧéxŧ !!]` and is handed to the page as its
  language; a walk through the menu, Play Now (a turn), Settings, Rules, Manager, Studio and Online counts lines still in plain
  English (text that never went through `_T`) and cut-off buttons/chips (the markers make strings longer, like a real
  translation), and checks that online refusals and raw errors reach the screen translated.
- `tools/tests/tv86.js` (+ `tv87l`) — the same walk in each real language.

## Rules of thumb

- Build whole sentences as one key; never glue translated pieces with English words between them.
- Never translate a string that is also used as an id or compared in code (mark the line `// i18n:skip`).
- CJK: no small-caps, letter-spacing or uppercase transforms (173-v89cjk).
